# 공개 앱 기능 명세 (`frontend/`)

**현재형 문서다** — [`README.md`](README.md) 의 갱신 규율을 먼저 읽는다.

Next.js + React. 발주자·개발자·방문자가 쓰는 앱이다. 운영자는 여기 들어오지 않는다
(ADR-0018 — 운영자와 참가자는 서로소다).

## 세 구역

| 구역 | 로그인 | 렌더링 |
| --- | --- | --- |
| 공개 | 필요 없다 | **서버 렌더링**(ADR-0015) — JS 를 꺼도 백엔드 값이 HTML 에 있다 |
| 콘솔 (`/console/*`) | 필요하다 | 미들웨어가 막는다 |
| 과제 (`/assignments/{code}`) | 필요하다 | 초대 코드로 여는 문 |

**공개 표면만 서버 렌더링한다**(ADR-0015). 페이지 하나에 `"use client"` 가 붙는 것만으로
조용히 깨지므로, e2e 가 그 사실 자체를 단언한다.

**콘솔 가드는 함수 하나다** — 미들웨어 `matcher` 가 `/console/:path*` 하나이고, 그
경로군 전체가 한 함수에 걸린다. 화면마다 반복해 확인하지 않는다.

## 토큰은 브라우저가 보지 않는다

**BFF 가 HttpOnly 쿠키로 토큰을 쥔다**(ADR-0016). 브라우저 JS 는 `document.cookie` 로
그 값을 볼 수 없다. 인증이 필요한 호출은 전부 `/api/backend/[...path]` 프록시를 지나며,
거기서 쿠키의 JWT 가 `Authorization` 헤더로 바뀐다.

방어는 둘이 함께 선다 — **허용목록**(무엇을 프록시할 것인가)과 **Origin 검증**. 하나만으로는
성립하지 않는다. 허용목록 검사 기계는 `packages/bff-shared` 에 있고, 목록의 **내용**은 앱마다
자기 파일에 남는다.

| BFF 라우트 | |
| --- | --- |
| `/api/backend/[...path]` | 백엔드 프록시 — 허용목록·Origin 검증·토큰 부착 |
| `/api/auth/session` | 지금 로그인 상태 |
| `/api/auth/social/{provider}/authorize` · `login` · `callback` | 소셜 로그인 |
| `/api/auth/logout` | 로그아웃 |

**우리 화면으로 돌아가는 리다이렉트는 상대 경로로 낸다.** 컨테이너 안의 Next 는 자기가 어떤
공개 주소로 불렸는지 모른다 — 리버스 프록시 뒤 standalone 모드에서 `request.url` 의 오리진이
바인드 주소로 나온다. 절대 URL 은 **외부로 나갈 때만** 쓴다.

## 화면이 스스로 판정하지 않는 것

**「지금 무엇을 할 수 있는가」는 서버가 답한다.** 화면이 마감 시각을 직접 비교하거나 상태를
재파생하지 않는다 — 새 상태가 생겼을 때 어느 분기에도 걸리지 않고 조용히 「알 수 없음」으로
떨어지기 때문이다. 서버가 enum 을 주면 생성된 타입에 값이 늘고 `tsc --noEmit` 이 누락된
분기를 빌드타임에 잡는다.

**API 타입은 손으로 쓰지 않는다.** `packages/bff-client/src/schema.gen.ts` 는 백엔드의
OpenAPI 스키마에서 생성해 커밋한 산출물이다. 재생성은 스택 없이 돈다.

## 테스트 시임은 실행 중인 앱 하나다

컴포넌트 테스트도 모킹도 그 아래로 내려가지 않는다(ADR-0017, ADR-0021). 개발 중에는
에이전트가 브라우저로 직접 걸어보고, 티켓이 끝날 때 스펙을 1~2개만 남긴다.

**남기는 기준**은 ADR-0017 의 세 위험(공개 페이지가 실제로 서버 렌더링되는가 · 인증 구역이
실제로 막히는가 · 프록시 허용목록과 Origin 검증이 실제로 막는가)과 **핵심 흐름**(돈이
움직이거나 보안이 새는 곳, 앱마다 유저스토리 한 벌)이다. 그 밖에는 남기지 않는다 — 대개
백엔드 테스트가 같은 사실을 이미 고정하고 있다.
