# 운영자 앱 기능 명세 (`operator/`)

**현재형 문서다** — [`README.md`](README.md) 의 갱신 규율을 먼저 읽는다.

Next.js + React. 공개 앱과 같은 3스테이지 이미지를 쓰지만 **다른 오리진에 뜬다.**

## 앱 전체에 걸리는 것

**왜 별도 앱인가 — Django admin 이 없기 때문이다**(ADR-0019). admin 은 모델 행을 직접
편집할 수 있어서, `Appeal`·`AppealRuling` 을 그 화면에서 고칠 수 있는 한 감사 추적에
우회로가 남는다. 사람이 판단하는 행위는 전부 `/api/operator/*` 를 지나고, 그 API 에 이
화면이 붙어 있다.

**운영자와 참가자는 서로소다**(ADR-0018). 계정 체계가 다르고 세션 방식이 다르다 — 운영자
세션은 운영에서 실제 Redis 에 산다. 공개 앱은 쿠키의 JWT 를 헤더로 바꿔 달지만, 운영자
앱은 **Django 세션 쿠키를 이름으로만 골라 중계한다** — 브라우저의 Cookie 헤더를 통째로
넘기지 않는다.

**가드가 셋이다.** 앱의 미들웨어, 백엔드 라우터의 기본 거부, 그리고 Origin 검증 미들웨어.
오리진 값은 백엔드와 운영자 앱이 같은 환경파일 줄 하나를 나눠 읽는다 — 어긋나면 로그인을
포함한 모든 변경 요청이 조용히 403 이 된다. fail-closed 라 구멍은 아니지만 원인을 찾기
어렵다(이 저장소가 이미 두 번 겪었다).

**미들웨어 `matcher` 는 화이트리스트가 아니라 예외 목록이다.** 로그인·API·헬스체크·정적
자산만 빼고 전부 막는다. 화이트리스트로 두면 **가드 없이 태어나는 페이지**가 생긴다 —
링크는 이미 살아 있는데 matcher 에 안 적힌 라우트가 그렇다. 실제로 홈이 아직 만들어지지
않은 화면으로 링크를 걸어 둔 적이 있다.

**공개 앱과 반드시 다른 서브도메인을 쓴다.** 같은 오리진을 공유하면 공개 앱이 뚫렸을 때
운영자 세션 쿠키까지 노출될 길이 생긴다.

**탭 파비콘만 있다.** 공개 앱·강의실과 같은 심볼(「커밋 노드 C」)을 주의색 타일에
그린 파비콘·홈 화면 추가 아이콘(`app/icon.tsx`·`app/apple-icon.tsx`)이 탭에서 이
앱을 한눈에 구별하게 한다 — 운영자가 실수로 다른 화면인 줄 알고 조작하지 않도록.
헤더 워드마크 로고·색인은 대상이 아니다(이 앱은 색인 대상이 아니고, 헤더는 화면
제목만 쓴다).

**배포 환경에서 필수 설정이 비면 부팅하지 않는다.** `instrumentation.ts` 가 첫 요청을 받기
전에 프로세스를 끊는다 — `throw` 만으로는 Next 가 그 에러를 삼켜 컨테이너가 Up 인 채로 이유
없는 500 만 낸다.

**등급이 둘이다.** 일반 운영자와 상위 등급(superuser). 상위 등급 전용 화면은 **비어 보이게
하지 않고 「등급이 필요하다」고 명시한다** — 「돈을 움직일 수 있다」와 「돈을 움직일 권한을
나눠줄 수 있다」는 무게가 다르기 때문이다.

**모든 변경 화면에 이력이 붙는다.** 정책·카테고리·산출물 종류·개최 권한(#414) —
누가·언제·무엇을·왜. 이력은 일반 등급도 본다.

# 화면

## `/login` 로그인

운영자 계정으로 로그인한다. 참가자 소셜 로그인과 아무것도 공유하지 않는다.

## `/` 홈

로그인한 운영자의 현관. **큐의 개수**를 보여줘 지금 사람 손이 필요한 곳이 어디인지 먼저
말하고, 각 화면으로 링크한다 — 이의 · 지급 · 정책 · 카테고리 · 산출물 종류 ·
신고된 템플릿 · 무료 공모전 개최 권한 · 운영팀 알림 · 무료 공모전 · 운영자 계정. 자기
등급도 보인다. 로그아웃이 있다.

**신고된 템플릿은 세 큐 카드에 나란히 있지 않다** — 그 셋은 #65가 정한 범위이고,
넷째 큐를 더하지 않는다(정책·카테고리·산출물 종류 링크와 같은 자리, 평문
링크뿐이다).

## `/appeals` 이의 목록

이의를 상태로 걸러 본다(대기 중 / 심판 완료 등). 필터는 URL 에 남아 새로고침해도 유지된다.
비었을 때·오류일 때의 문구가 따로 있다.

## `/appeals/[id]` 이의 심판

**이 앱에서 가장 무거운 화면이다.** 판정을 사람이 내리고, 그 결과가 돈으로 이어진다.

보이는 것:
- 이의를 낸 **제출물**과 **제기 사유**, 접수 시각.
- **채점 스냅샷** — 달성률 · 판정 모델 · Requirement 별 판정 근거 · 채점 시각. 참가자가
  보는 것과 **같은 사실**을 본다. 이의를 낸 사람과 심판하는 사람이 다른 것을 보고 이야기하면
  이의는 서로 다른 근거를 두고 오간다.
- **소스** — 접혀 있다. **펼치기 전에 「펼치면 이 열람이 기록되고 Developer 가 자기 제출물의
  열람 기록에서 그것을 본다」고 말한다.** 행위 이후가 아니라 이전에 알려야 그 기록이
  억제력이 된다(ADR-0022).
- 이미 심판이 있으면 **결정 · 보정 금액 · 심판 메모 · 심판자 · 심판 시각**.

할 수 있는 것 — **심판이 아직 없을 때만** 나온다:
- **인용(uphold)** — 보정 금액을 함께 낸다.
- **기각(reject)**.
- 두 경우 모두 **심판 메모**를 남긴다.

**Score 를 고치지 않는다**(ADR-0006). 인용의 결과는 점수 수정이 아니라 **원장에 남는
보정**이다.

## `/payouts` 지급 큐

지급이 **무엇에 막혀 있는지**를 보여주는 화면. 목록은 개발자 · 공모전 · 금액을 행으로 갖고,
필터와 총 건수·총액이 붙는다. 더 보기로 이어 받는다.

**설명 문구가 화면에 있다** — 이 큐가 무엇을 뜻하는지, 어떤 상태가 왜 여기 남는지. 그것이
없으면 운영자는 「막혔다」와 「아직 안 왔다」를 구별하지 못한다.

**재시도**를 걸 수 있고, 실패하면 그 사유가 화면에 남는다.

## `/policy` 플랫폼 정책

수수료율 · 원천징수 · 개최 등록비 · 심사기간 · 인수 기간 · 배분 대기 · 리마인더 선행 시간 ·
자료 개수 상한 · 판매자 한도를 본다.

**정책은 DB 에 살고 이 화면으로만 바뀐다**(ADR-0023). 코드 상수가 아니다 — 값 하나 바꾸려고
배포하지 않는다. 모든 변경이 **이력**으로 남는다(누가·언제·무엇을·왜). 편집 권한이 없으면
그렇다고 말한다.

## `/categories` 카테고리 · `/deliverable-types` 산출물 종류

**두 화면의 모양이 같다.** 목록을 보고, 새로 만들고, 이름을 바꾸고, **비활성화**한다.
삭제가 아니라 비활성화다 — 이미 그것을 참조하는 공모전이 있기 때문이다.

변경 이력이 함께 있다. 편집 권한이 없으면 목록만 본다.

산출물 종류에는 **최소 제안 상금**이 붙는다 — 공개 목록의 「상금미달」 표시가 그 값에서
나온다.

## `/problem-template-reports` 신고된 템플릿(#320)

강의실 강사가 공개한 템플릿(#316)이 신고되면 여기 뜬다 — 미리 심사하지 않고
바로 공개하되 신고로 내릴 수 있게 한 설계의 짝이다. 각 줄이 제목·설명·올린
사람이 적은 이름·신고 수·신고 사유들을 보인다.

**「내리기」또는 「기각」을 고르고 이유를 남긴다.** 둘 다 판단이라 누가·언제·왜가
기록으로 남는다 — 기각도 기록된다. 화면이 **「내려도 이미 가져간 사람의
문제·클래스는 영향을 받지 않는다」**고 미리 말한다 — 그건 설계의 결과(템플릿은
사본이다)이지 이 조작의 한계가 아니다.

기각한 뒤 같은 템플릿이 다시 신고되면 대기열에 다시 뜬다 — 새 신고는 새 사건이다.

## `/hosting-permissions` 무료 공모전 개최 권한 (#414, ADR-0048)

계정별로 「무료 공모전 개최 권한」을 켜고 끈다 — 유료 공모전에서는 결제가 개최를
걸러 주지만 무료 공모전에는 그 문이 없으므로, Operator 가 사람을 지정해 대신
선다(CONTEXT.md 「개최 권한」).

**이메일·닉네임으로 계정을 찾는다.** `User.username` 은 소셜 로그인이 지어낸
값(`kakao:12345` 꼴)이라 검색어로 쓸 수 없다 — 사람이 읽을 이름은 소셜 로그인
닉네임이다. 검색 결과 각 줄에 지금 권한 여부가 함께 보이고, 그 자리에서 바로
켜고 끌 수 있다.

**켜고 끄는 것은 상위 등급만, 사유가 필수다** — 카테고리·산출물 종류와 같은
무게의 판단이다(누가 상금 없이 공모전을 열 수 있는지를 정한다). 조회(검색·보유
목록·이력)는 일반 등급도 된다. 이미 그 상태면(이미 켜져 있는데 또 켜려는 등)
막는다 — 실제로 바뀐 것만 이력에 남긴다.

**권한 보유 계정 목록**이 따로 있다 — 지금 누가 열 수 있는지 검색 없이 한눈에
본다. **변경 이력**은 누가·언제·누구를·부여인지 회수인지·왜를 보여준다.

**권한을 꺼도 그 계정이 이미 연 공모전은 영향받지 않는다** — 이 화면은 권한
행만 바꾸고 Contest 는 건드리지 않는다. 권한으로 실제 무료 공모전을 여는
것(공개 앱의 개최 화면)은 이 화면의 몫이 아니다(#415).

## `/operators` 운영자 계정

**상위 등급 전용이다.** 계정 목록·등급을 보고, 만들고, 비활성화·재활성화한다.

**첫 운영자는 이 화면으로 만들 수 없다** — 들어오려면 이미 운영자여야 하기 때문이다.
관리 명령으로 만든다. `createsuperuser` 는 쓰지 않는다(운영자와 참가자가 서로소라는
불변식을 모른다).

## `/notifications` 운영팀 알림(#418/#419, CONTEXT.md 「운영자 알림」)

**검색 → 작성(이미지 포함) → 확인 → 보내기, 그리고 이력.** 이메일이나 닉네임으로
받는 사람 계정을 찾아 한 사람을 고르고, 제목(필수)·본문(선택)·이미지 한 장
(선택, png·jpeg·webp)을 쓴 뒤 확인 화면에서 받는 사람·제목·본문·첨부 여부를
다시 보고서야 실제로 보낸다 — 잘못 보내지 않기 위해서다. 한 번에 한 사람에게만
보낸다(사람마다 다른 보상을 실수로 섞어 보내지 않기 위해서다). 형식·크기가
맞지 않는 이미지는 올리기 전에 이유를 보인다.

**보낸 뒤에는 고칠 수 없다.** 수정·삭제 버튼이 없다 — 잘못 보냈으면 새 알림을
다시 보낸다. 아래 이력 표는 받는 사람·제목·보낸 운영자·시각·읽음 여부를
최신순으로 보여주고, 이미지가 첨부된 줄은 「이미지 보기」로 다시 열어 볼 수
있다 — 무엇을 보냈는지 확인하기 위해서다.

등급을 가리지 않는다 — `OperatorAuth`면 충분하다. 계정 검색으로 들어오면
검색 단계부터 시작하고, 아래 `/contests/free` 의 수상자 옆 바로가기로 들어오면
받는 사람이 이미 채워진 작성 단계부터 시작한다(쿼리로 실어 온다, 검색을
한 번 더 거치지 않는다) — 둘 다 같은 화면·같은 흐름이다.

## `/contests/free` 무료 공모전 (#420, ADR-0048)

**상태·마감·수상 여부·수상자를 한눈에 본다.** `GET /operator/contests/free`
가 `is_free=True` 인 Contest 만 돌려준다 — 유료 공모전은 이 목록에 아예
섞이지 않는다(상금·본인확인·환불 같은 유료 전용 개념이 없는 목록이라 구별
플래그 대신 필터로 뺐다). 등급을 가리지 않는다 — 조회 전용 화면이라 편집
가능 여부를 가를 것이 없다.

**수상하면 그 줄에 수상자(이메일·닉네임)가 뜨고, 그 옆에 「운영팀 알림
보내기」가 생긴다.** 아직 심사 중이거나 심사 기간 안에 고르지 않고 끝난
줄은 수상자 자리가 비어 있고 그 버튼도 없다. 버튼을 누르면 위
`/notifications` 화면이 그 수상자를 받는 사람으로 채운 채 열린다 — 수상자를
따로 찾지 않고 바로 보상(기프티콘 등)을 전하기 위해서다.

## 화면이 없는 것

**신원 열람**(`/api/operator/retained-identities/*`)은 API 만 있다. 화면이 없는 조작은
운영자가 HTTP 로 직접 친다.

**과제 개최 자격**은 화면도 API도 모델도 없다 — 과제를 접기로 하며(#358)
화면(#360)·API(#361)·모델(#363)이 차례로 걷혔다.

## 이 앱이 하지 않는 것

- **모델 행을 직접 고치지 않는다.** 각 화면은 그 행위를 위한 API 를 부르고, 그 API 가
  불변식과 이력을 함께 챙긴다.
- **원장을 고치지 않는다.** 분개는 append-only 이고, 잘못된 판정의 구제는 되돌리기가 아니라
  **반대 분개**다(ADR-0004).
- **Score 를 고치지 않는다.** 불변이다(ADR-0006).

## 오류 화면과 오류 수집 (2026-09-16)

화면이 깨지면 「문제가 생겼습니다 · 다시 시도 · 홈으로」를 보여 주고, 그 오류를 자체
GlitchTip 으로 보낸다(`app/error.tsx`). 레이아웃 자체가 터진 경우의 마지막 그물은
`app/global-error.tsx` 다 — 앱 서체·토큰 없이 브라우저 기본 모양으로 뜨지만 어떤
상황에서도 뜬다. 무엇이 잘못됐는지는 사용자에게 적지 않는다(오류 메시지에 내부
사정이 섞여 나올 수 있다) — 진단은 수집된 오류로 한다. 서버(Node)에서 난 오류도 같은
프로젝트로 간다. DSN 이 없으면 수집은 꺼지고 화면만 그대로 돈다. 자세한 규율은
`CLAUDE.md` 「운영」의 오류 수집 절에 있다.

## 테스트

앱마다 시임이 하나다(ADR-0021). 운영자 앱 스펙은 `frontend/e2e/operator/*.spec.ts` 에 있고
Playwright 가 프로젝트 둘로 두 앱을 한 번에 친다. e2e 가 로그인할 운영자 계정은 멱등한 시드
명령이 만든다 — 사람이 쓰는 부트스트랩 명령과 달리 반복 실행에 안전하다.
