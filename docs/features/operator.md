# 운영자 앱 기능 명세 (`operator/`)

**현재형 문서다** — [`README.md`](README.md) 의 갱신 규율을 먼저 읽는다.

Next.js + React. 공개 앱과 같은 3스테이지 이미지를 쓰지만 **다른 오리진에 뜬다.**

## 왜 별도 앱인가

**Django admin 이 없기 때문이다**(ADR-0019). admin 은 모델 행을 직접 편집할 수 있어서,
`Appeal`·`AppealRuling` 을 그 화면에서 고칠 수 있는 한 감사 추적에 우회로가 남는다. 사람이
판단하는 행위는 전부 `/api/operator/*` 를 지나고, 그 API 에 이 화면이 붙어 있다.

**운영자와 참가자는 서로소다**(ADR-0018). 계정 체계가 다르고 세션 방식이 다르다 — 운영자
세션은 운영에서 실제 Redis 에 산다.

**공개 앱과 반드시 다른 서브도메인을 쓴다.** 같은 오리진을 공유하면 공개 앱이 뚫렸을 때
운영자 세션 쿠키까지 노출될 길이 생긴다.

## 인증의 모양이 다르다

공개 앱은 쿠키의 JWT 를 `Authorization` 헤더로 바꿔 달지만, 운영자 앱은 **Django 세션
쿠키를 이름으로만 골라 중계한다** — 브라우저의 Cookie 헤더를 통째로 넘기지 않는다.

**가드가 셋이다.** 앱의 미들웨어, 백엔드 라우터의 기본 거부, 그리고 Origin 검증 미들웨어.
오리진 값은 백엔드와 운영자 앱이 같은 환경파일 줄 하나를 나눠 읽는다 — 어긋나면 로그인을
포함한 모든 변경 요청이 조용히 403 이 된다. fail-closed 라 구멍은 아니지만 원인을 찾기
어렵다(이 저장소가 이미 두 번 겪었다).

**미들웨어 `matcher` 는 화이트리스트가 아니라 예외 목록이다.** 로그인·API·헬스체크·정적
자산만 빼고 전부 막는다. 화이트리스트로 두면 **가드 없이 태어나는 페이지**가 생긴다 —
링크는 이미 살아 있는데 matcher 에 안 적힌 라우트가 그렇다.

**배포 환경에서 필수 설정이 비면 부팅하지 않는다.** `instrumentation.ts` 가 첫 요청을 받기
전에 프로세스를 끊는다 — `throw` 만으로는 Next 가 그 에러를 삼켜 컨테이너가 Up 인 채로 이유
없는 500 만 낸다.

## 화면

| 경로 | 무엇을 하는가 |
| --- | --- |
| `/login` | 운영자 로그인 |
| `/` | 홈 — 각 화면으로 |
| `/appeals` · `/appeals/[id]` | **이의 심판** — 목록·상세·판정. 채점 스냅샷을 원문 그대로 보고, 필요하면 소스를 열람한다 |
| `/payouts` | **지급 큐** — 무엇이 무엇에 막혀 있는지(`blocked_on`), 재시도 |
| `/policy` | **플랫폼 정책** — 수수료·원천징수·기간·상한. 모든 변경이 이력으로 남는다 |
| `/categories` | 카테고리 — 생성·이름 변경·비활성화, 변경 이력 |
| `/deliverable-types` | 산출물 종류 — 같은 모양 |
| `/assignment-permissions` | 과제 개설 자격 — 부여·회수, 변경 이력 |
| `/operators` | 운영자 계정 — 생성·비활성화·재활성화 |

**첫 운영자는 화면이 아니라 관리 명령으로 만든다** — 계정 관리 화면에 들어가려면 이미
운영자여야 하기 때문이다. `createsuperuser` 는 쓰지 않는다(운영자와 참가자가 서로소라는
불변식을 모른다).

## 화면이 없는 것

**신원 열람**(`/api/operator/retained-identities/*`)은 API 만 있다. 화면이 없는 조작은
운영자가 HTTP 로 직접 친다.

**소스 열람은 어디서 하든 기록된다**(ADR-0022). 이의 심판을 위해 볼 수 있다는 것과 아무도
모르게 볼 수 있다는 것은 다르다.

## 이 앱이 하지 않는 것

- **모델 행을 직접 고치지 않는다.** 각 화면은 그 행위를 위한 API 를 부르고, 그 API 가
  불변식과 이력을 함께 챙긴다.
- **원장을 고치지 않는다.** 분개는 append-only 이고, 잘못된 판정의 구제는 되돌리기가 아니라
  **반대 분개**다(ADR-0004).
- **Score 를 고치지 않는다.** 불변이다(ADR-0006). 이의 심판의 결과는 점수 수정이 아니라
  원장에 남는 조정이다.

## 테스트

앱마다 시임이 하나다(ADR-0021). 운영자 앱 스펙은 `frontend/e2e/operator/*.spec.ts` 에 있고
Playwright 가 프로젝트 둘로 두 앱을 한 번에 친다. e2e 가 로그인할 운영자 계정은 멱등한 시드
명령이 만든다 — 사람이 쓰는 부트스트랩 명령과 달리 반복 실행에 안전하다.
