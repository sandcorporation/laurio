# 정책값은 DB에 살고 운영자 API로만 바뀐다

Status: Accepted (2026-09-01 결정)

수수료율·원천징수율·개최비·연장비·심사기간·배분 대기일·배분 컷라인 같은 값들이 세 곳에 흩어져 있었다. 대부분은 `settings.py`가 환경변수로 읽었고(12개, 200줄 범위에 산재), 컷라인과 DeliverableType의 최소 제안 상금은 DB 테이블에 있었고, 소스 선별 상한 같은 것은 코드에 박혀 있었다.

**그리고 환경변수 쪽은 실제로는 아무도 주지 않고 있었다.** `backend/.env.example`에 요율이 문서화되어 있지만 staging·prod compose 어디에도 그 값이 없다 — 두 배포 환경 모두 코드 기본값으로 돈다. "환경변수로 관리 가능"이 "코드 상수"와 같은 상태였다.

**DB 쪽 둘은 조정 수단을 잃은 채였다.** 두 모델의 docstring이 "운영자가 Django admin에서 직접 값을 바꾼다"고 말하는데, admin은 ADR-0019로 내려갔다. "배포 없이 바꿀 수 있어야 한다"는 이유로 테이블에 뒀는데 바꿀 방법이 `manage.py shell`과 psql 뿐이었다.

**정책값은 전부 DB의 단일 행에 두고, 운영자 API로만 바꾼다.**

## 왜 환경변수가 아닌가

**이 값들은 환경의 성질이 아니라 사업 정책이다.** staging과 production의 수수료가 다르면 그것은 설정이 아니라 버그다. 환경변수는 "환경마다 달라야 하는 것"을 위한 자리이고, 요율은 그 반대다 — 어디서 돌든 같아야 한다.

**그리고 요율을 바꾸는 것은 사람의 판단이다.** ADR-0019가 "사람이 판단하는 행위는 `/api/operator/*` 로만 한다"고 정한 이유가 여기에도 그대로 적용된다. 수수료를 10%에서 12%로 올리는 것은 돈에 관한 결정이고, **누가 언제 무엇을 무엇으로 바꿨는지가 남아야 한다.** 환경변수는 그 기록을 남기지 않는다 — 컨테이너를 다시 띄우면 이전 값이 어디에도 없다.

`AppealRuling`이 심판에, `SourceReading`이 열람에 신원을 붙인 것과 같은 규율이다.

## 왜 단일 행인가

값마다 테이블을 두거나 key-value 행으로 흩으면 조회가 값의 수만큼 늘어난다. 채점·배분·지급 경로가 요율을 읽을 때마다 쿼리가 나가는 구조는 만들지 않는다. 정책은 행 하나로 읽고, 그래서 "우리 정책이 무엇인가"가 행 하나다.

`DeliverableType`의 최소 제안 상금만 예외다 — 종류마다 값이 다르고 종류 자체가 추가·삭제되므로 단일 행에 들어갈 수 없다. 별도 테이블로 남기되 운영자 API는 같이 붙는다.

## Consequences

**적용된 요율을 스냅샷에 박아야 한다.** 값이 바뀔 수 있게 되는 순간 "이 지급은 왜 이만큼 뗐는가"에 답할 수 있어야 한다. `Distribution`은 이미 `cutline_percentage`로 그때 쓴 값을 기억하지만 `Payout`은 금액만 남기고 요율을 남기지 않는다 — 상금이 다르면 금액에서 역산이 안 되므로, 요율 자체를 남긴다. ADR-0006이 `Score`에 대해 세운 불변 스냅샷과 같은 이유다.

**테스트는 이 이전 때문에 바뀌지 않는다.** 기간이 DB로 가면 dev·CI가 짧게 잡지 못해 테스트가 느려질 것처럼 보이지만, 확인해보니 이 저장소의 테스트는 **값을 바꾸지 않고 시계를 옮긴다** — `override_settings`로 기간을 바꾸는 테스트가 하나도 없고, 15개 파일이 시계를 직접 다룬다. ADR-0003이 "시간은 시임이 아니라 주입 가능한 의존성"으로 정해둔 것이 이 이전을 싸게 만들었다.

**부팅 시점 검증을 잃는다.** 시크릿·오리진처럼 "없으면 뜨지 않는다"를 걸 수 없고, 잘못된 값은 런타임에야 드러난다. 다만 요율에는 합리적 기본값이 있어 행이 없으면 기본값으로 만들면 되므로, 시크릿에서와 같은 위험은 아니다.

**환경변수로 요율을 주던 경로는 사라진다.** `backend/.env.example`에서 그 항목들을 빼고, 값을 바꾸는 방법이 운영자 API 하나가 되게 한다. 두 경로가 남으면 어느 쪽이 이겼는지 아무도 모른다 — 이 저장소가 CSRF 방어를 두 기계로 두었다가 겪은 사고와 같은 모양이다.
