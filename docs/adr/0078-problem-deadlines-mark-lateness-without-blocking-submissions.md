# 문제 마감 뒤에도 제출을 받고 늦음을 두 단계로 표시한다

Status: Accepted (2026-11-10 결정)

## 맥락 (#941)

ADR-0063은 권장 기한 뒤를 늦음으로 표시하고 마감 뒤 참여자 제출은 막았다. 대표는 학습 중 다시 내는
흐름을 마감 뒤에도 이어 가기로 결정했다. 기존 boolean 늦음으로는 권장 기한과 마감을 구분할 수 없다.

## 결정

- 모든 문제에서 마감 뒤 참여자 제출을 받는다. 설정은 추가하지 않고 이미 마감된 문제에도 바로 적용한다.
  별도 알림·데이터 이행은 없다. 보관·내보냄·숨김·초안의 접근 규칙과 강사 제출 규칙은 유지한다.
- `late`는 `null | "recommended" | "deadline"`이다. 제출 시각이 마감보다 뒤면 `deadline`, 그렇지 않고
  권장 기한보다 뒤면 `recommended`, 나머지는 null이다. 경계 시각 자체는 늦지 않다. 마감이 우선이고
  권장 기한이 없어도 마감 뒤를 표시한다.
- 시도 응답은 그 시도, 참여자 문제 목록·강사 명단 격자·MCP 참여자 리포트는 마지막 시도를 기준으로
  응답마다 계산한다. 저장하지 않으므로 날짜를 옮기면 지난 시도 표시도 바뀐다. 통과 이력 판정은 그대로다.
- 강사 명단 격자는 권장 기한 뒤의 기존 점을 유지하고 마감 뒤는 주의색 토큰의 더 큰 점으로 구분한다.
  범례와 칸 설명에 두 단계 이름을 적는다. 참여자 상태 배지는 「· 권장 기한 뒤」·「· 마감 기한 뒤」다.
- 마감 뒤 제출 카드에는 「마감이 지났습니다 — 지금 내면 「마감 기한 뒤 제출」로 표시됩니다」를 안내하고
  제출 입력·버튼을 활성화한다. 새 문제·수정의 마감 칸도 제출 허용과 마감 뒤 표시를 설명한다.
- 권장 ≤ 마감 검증, nullable 날짜, 복사·템플릿에서 날짜를 비우는 규칙, 채점은 바뀌지 않는다.

## 결과

DB 스키마 변경은 없다. API의 늦음 타입과 화면·MCP 소비처를 함께 바꾼다. 마감 뒤 제출, 경계·우선순위,
마지막 시도 기준, 기존 차단 유지와 MCP 결과를 HTTP 시험으로 확인한다. 화면의 상태 글자는 vitest로 확인한다.
