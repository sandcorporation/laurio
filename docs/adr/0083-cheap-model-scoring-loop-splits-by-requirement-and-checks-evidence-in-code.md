# 싼 모델용 채점 루프는 요구사항마다 문맥을 나누고, 근거는 코드가 박제본에서 확인한다 — 실험용 셋째 방식

Status: Accepted (2026-11-21 결정)

ADR-0082(CLI 에이전트 채점) 옆에 셋째 방식을 **실험용으로** 더한다. 운영 채점 경로와 `CONTEST_SCORING_METHOD` 는 그대로다.

## 맥락 (스펙 #1244, 티켓 #1245, 대장 #4334·#4337·#4340·#4343)

지금 에이전트 방식은 CLI(Claude Code·Codex)가 한 문맥에서 요구사항 전부를 들고 저장소를 돈다. `claude-sonnet-5-5` 에서는
쓸 만했지만 싼 모델(`claude-haiku-5-5`, `gpt-4.1-mini`)은 약점이 셋이다: 문맥이 길어지면 길을 잃고, 읽지 않은 줄을 근거로
대고, 출력 꼴을 깬다. Haiku 에는 엄격 규칙(#1048)을 붙였지만 **규칙은 부탁일 뿐 확인이 아니다** — 지킨 줄을 CLI 밖에서
다시 볼 길이 없었고, 받아들이는 조건(#1000)은 근거 파일·줄이 있는가까지만 본다. 방식·모델을 운영 점수에 닿지 않게 견줄
도구도 없었다(#1246 이 만든다).

## 결정

1. **루프는 새로 만들고, `agent-grader` 안의 셋째 갈래(`selfloop`)로 둔다.** 격리(외부망 없음·읽기 전용 루트·seccomp·
   비루트)와 실행 토큰·`llm-proxy` 예산은 CLI 갈래와 같다. CLI 를 띄우지 않고 실행기 프로세스가 프록시를 직접 부른다 —
   Anthropic Messages tool use 와 OpenAI Responses function calling 을 **어댑터 하나**(대화 한 개의 `send`·`add_tool_result`·
   `add_user`)로 감싸 루프는 벤더를 모른다. 실행기 파일처럼 표준 라이브러리만 쓴다(이미지가 두 파일만 복사한다).
2. **단계를 나눈다.** ① 지도: 파일 트리와 요구사항 목록만 보고 요구사항마다 파일 후보를 낸다. ② 요구사항마다 **새 문맥**의
   하위 루프: 그 요구사항 하나와 후보만 받는다. 앞 요구사항의 읽기 결과가 뒤 요구사항의 문맥을 채우지 않는다 — 긴 문맥에서
   길을 잃는 약점을 구조로 막는다. 대가는 같은 파일을 요구사항마다 다시 읽는 토큰이다(비용은 #1246 이 잰다).
3. **근거는 코드가 확인한다.** 모델이 댄 `경로:줄` 마다 실행기가 박제본에서 파일이 있는지, 줄 범위가 맞는지, 그 줄이 비거나
   주석·import 만은 아닌지 본다. 틀리면 실제 줄을 붙여 다시 묻고(최대 2번), 그래도 틀리면 **미충족 + 「근거 확인 불가」**다.
   보류가 아니라 미충족인 까닭: 근거를 못 대는 충족 주장은 채점 규칙 3·4(구현 코드가 있을 때만 충족)에 비추어 충족이 아니고,
   보류하면 같은 실행을 다시 돌려 비용만 쓴다.
4. **판정은 제출 도구로만 받는다.** 꼴이 깨지면 오류를 붙여 다시 묻고(최대 2번), 글만 내고 끝나면 한 번 재촉한다. 그래도
   판정이 없거나 턴 한도(하위 루프마다 8턴)·실행 전체 300초·프록시 예산(429)에 닿으면 그 요구사항은 **판정 없음**이고,
   부르는 쪽은 그 실행을 보류한다(0% 로 굳히지 않는다, ADR-0031).
5. **도구는 읽기 넷**(`list_dir`·`glob`·`grep` 결과 50줄·`read_file` 한 번 20KB)이다. 박제본 루트 밖은 심볼릭 링크로도
   나가지 못하고, 같은 호출·같은 파일 범위의 반복은 막고 모델에게 알린다(싼 모델이 같은 파일을 되읽으며 턴을 쓴다).
6. **운영에는 넣지 않는다.** 부르는 함수(`scoring.selfloop_scoring.run_selfloop_scoring`)는 벤더·모델을 인자로 받고 운영 표에
   쓰지 않는다. `CONTEST_SCORING_METHOD=self_loop` 선택지는 #1246 의 비교가 통과 기준(평균 점수 차 5점 이하, 3회 흔들림이
   같거나 작음, 근거 실재율 95% 이상, 비용이 더 쌈 — 기준은 에이전트 + `claude-sonnet-5-5`)을 넘은 뒤 따로 결정한다.

## 결과

- 실행 기록은 `AgentRun.record` 와 같은 키에 루프 기록(단계·요구사항별 토큰과 비용, 다시 물은 횟수, 근거 탈락 수, 시간)을
  더한 꼴이다 — 비교 실험이 CLI 갈래와 같은 자리에서 읽는다. `model_version` 은 `agent:selfloop:<모델>`.
- 「근거 실재」가 정의상 100% 가 된다(확인하지 못한 근거는 판정에 남지 않는다). 그래서 비교의 근거 실재율은 **처음 낸 근거**
  기준으로도 따로 본다(`evidence_dropped`).
- 실행기 이미지가 파일 둘(`agent_runner.py`·`selfloop.py`)을 복사한다 — 바뀌면 `deploy.sh`·`image_context.py` 가 그
  이미지를 다시 굽는다.
