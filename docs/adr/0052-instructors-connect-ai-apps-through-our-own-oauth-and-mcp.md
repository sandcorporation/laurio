# 강사는 우리가 직접 여는 OAuth·MCP 로 외부 AI 앱을 연결한다 — 참여자 소스도 거기로 나갈 수 있다

Status: Accepted (2026-10-03 결정)

강사가 Claude 같은 외부 AI 도구로 클래스를 다루게 한다 — 문제를 만들고 고치고 숨기고 지우고,
참여자 리포트와 제출 소스를 읽는다. 이를 위해 **백엔드가 원격 MCP 서버와 MCP 규격의 OAuth 2.1 인가
서버를 함께 연다**(강의실 도메인 아래 `/mcp`). 강사가 한 번 허락하면 그 「연결된 앱」은 그 강사의
모든 Class 에 화면과 같은 일을 한다(OpenAI 키를 넣는 것만 뺀다).

## 왜 이 모양인가

- **OAuth 인가 서버를 직접 둔다.** claude.ai 의 커넥터는 주소 하나로 붙고 로그인은 OAuth 로만 한다 —
  개인 토큰을 헤더에 넣는 방식은 Claude Code·Desktop 에서만 되고 웹에서는 안 된다. 강의실의 로그인은
  5분짜리 JWT 와 부모 도메인 쿠키뿐이라(ADR-0038) 기존 장치로는 줄 수 없다. 외부 인가 서비스를 쓰지
  않는 이유는 GlitchTip 과 같다 — 계정과 수업 제출물이 바깥 업체에 묶이지 않는 편이 낫다.
- **참여자 소스가 강사가 고른 외부 AI 로 나갈 수 있다.** 강사는 이미 화면에서 소스를 연다(ADR-0040).
  연결된 앱은 같은 것을 강사가 고른 도구로 여는 것이고, 그 도구가 바깥 업체라는 점이 새롭다. 참여자별
  동의나 클래스별 스위치를 두지 않고 **개인정보 처리방침과 이용약관에 적는 것**으로 알린다 — 동의를
  받으면 리포트에 구멍이 나고, 스위치는 「강사의 모든 클래스」라는 허락과 따로 논다.
- **읽기는 기록하지 않고 쓰기만 기록한다.** ADR-0040 이 강의실에서 열람을 기록하지 않기로 한 이유가
  그대로 맞다. 다만 AI 가 엉뚱하게 고친 것을 강사가 되짚을 수 있어야 해서, 연결된 앱이 바꾼 것은
  어느 앱이 언제 어느 도구로 했는지 남긴다.

## 고려한 대안

- **로컬 설치형(stdio) MCP** — 서버 쪽 일이 가장 적지만 강사마다 Node 설치가 필요하고 웹 클라이언트에는
  붙지 못한다.
- **개인 토큰만** — 만들 것이 작고 나중에 OAuth 를 얹을 수 있지만, claude.ai 웹에서 쓰지 못한다.
- **클래스를 골라 허락 / 읽기·쓰기를 나눠 허락** — 안전하지만 새 클래스마다 다시 허락해야 하고 동의 화면이
  복잡해진다. 대신 되돌릴 수 없는 행위(삭제·내보내기·템플릿 공개)는 두 단계 확인으로 막는다.

## 결과

- 인가 서버가 생긴다 — 동적 클라이언트 등록·동의 화면·토큰 발급과 회수·「연결된 앱」 목록과 끊기를 우리가
  유지한다. 허락은 끊을 때까지 가되 90일 쓰지 않으면 만료하고, 탈퇴·휴면이면 곧바로 끊긴다.
- 연결된 앱의 호출은 강사당 분당 상한을 받는다(prod 는 코어 4).
- 유료 기능이나 열람 기록이 들어오면 ADR-0040 과 함께 이 ADR 도 다시 본다.
