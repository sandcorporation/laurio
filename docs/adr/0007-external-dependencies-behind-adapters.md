# PG·LLM 등 외부 의존성은 어댑터 뒤에 두고 환경별로 교체한다

Status: Accepted (2026-08-28 결정)

돈이 새는 경로는 정상 흐름이 아니라 장애 흐름이다 — 웹훅 중복 수신, 웹훅이 결제 승인보다 먼저 도착, 지급 API 타임아웃 후 실제로는 성공, 1/N 배분 중 일부만 성공. PG 샌드박스로는 이걸 재현할 수 없다. 저쪽이 언제 무엇을 보낼지 우리가 정할 수 없기 때문이다. PG·LLM·스토리지·메일을 인터페이스로 감싸고 구현체를 환경별로 갈아끼운다.

## Consequences

dev는 Fake PG 컨테이너로 웹훅 재전송·타임아웃·부분 실패를 의도적으로 주입해 돈이 새는 경로를 테스트한다. staging은 토스 샌드박스로 실제 연동 규약만 검증하고, prod는 실물을 쓴다. LLM도 같은 구조라 채점 플로우를 CI에서 비용 없이 돌릴 수 있다. 대가로 어댑터 경계를 설계·유지하는 비용이 상시로 든다.
