# 「완벽」은 통과 위의 판정이고 저장하지 않고 센다 — 선택 항목은 강의실에서 「심화」로 보인다

Status: Accepted (2026-11-19 결정)

## 맥락

강사가 잘하는 학생에게 「안 해도 통과지만 더 해 볼 수 있는 것」을 보여 주고, 다 해내면 보상 표시를 주고 싶어 한다.
「선택」 등급의 채점 방식이 이미 그렇다(AI 가 판정하되 통과에 들어가지 않는다). 다만 학생들이 「선택」이라는 이름을
헷갈려 한다. 통과(ADR-0067·0073)는 `Problem.is_score_passed` 가 **지금의 체크리스트로 다시 센다**.

## 결정 (spec #960, 구현 #962)

1. **이름**: 강의실 화면에서만 「선택」을 「심화」로 보인다. 공모전은 「선택」 그대로다. 내부 값(`optional`)·채점·MCP
   스키마 값은 바꾸지 않는다 — 기존 문제의 선택 항목이 곧바로 심화로 보인다. MCP 도구 설명 글만 「강의실 화면에서는
   심화로 보인다」로 맞춘다.
2. **판정 단계 추가**: 한 시도에서 필수와 심화 항목이 전부 충족이면 「완벽」이다(`Problem.is_score_perfect`).
   - 통과와 같은 규칙: 확인 불가는 충족이 아니고, 숨긴 심화 항목도 들어가며, 가산 항목은 뺀다. 문법 검사 등 통과의 조건도
     그대로 요구하므로 완벽은 통과의 부분집합이다.
   - **저장하지 않고 센다.** 컬럼·마이그레이션이 없다. 강사가 뒤에 심화 항목을 더하거나 고치면 완벽도 다시 센다 —
     「한 번 달성하면 유지」는 「지금 체크리스트로 센 시도 가운데 하나라도 완벽」이다.
   - 심화 항목이 없는 문제에는 완벽이 없다. 응답은 `false`/`0` 이 아니라 `null` 이다(없음과 못 함을 가른다).
3. **여러 시도**: 문제 단위는 어느 시도든 한 번 완벽이면 완벽이다(통과와 같은 OR). 시도별 응답은 그 시도의 판정이다.
4. **완성도와 별개다**(ADR-0072·0073). 완성도 점수를 완벽의 기준에 쓰지 않는다.
5. **응답 칸**(이름이 화면과 같다):

   | 응답 | 칸 |
   | --- | --- |
   | 시도(참여자·강사) | `perfect: bool \| null` |
   | 문제(참여자 상세 `problem`·문제 목록 줄) | `perfect: bool \| null` (시도 전체의 OR) |
   | 강사 문제 응답(`ProblemOut`)·격자 문제 열 | `perfect_count: int \| null` |
   | 격자 칸(참여자 × 문제) | `perfect: bool \| null` |

   `passed` 가 이미 실린 곳마다 옆에 싣고, 통과 수를 세는 같은 시도 묶음을 한 번 훑어 함께 센다 — 질의는 학생·시도 수에
   따라 늘지 않는다.

## 되돌리는 법

저장한 값이 없다. 응답에서 새 칸을 빼고 `is_score_perfect` 를 지우면 끝이다(마이그레이션 없음). 화면 문구의 「심화」는
화면 티켓(#963·#964)이 가져온다.

## 결과

- 화면이 도장·강사 현황을 그리는 데 필요한 값이 백엔드에 있다.
- 기존 응답에 칸만 더했으므로 옛 프런트는 그대로 동작한다.
