# 파일은 항상 private 버킷에 두고 presigned URL로만 접근한다

제출물에는 수백 MB짜리 앱 빌드와 시연 영상이 들어오는데, 마감 직전 동시 업로드가 앱 워커를 점유하면 마감 자체가 깨진다. 더 큰 문제는 접근 제어다 — 마감 시각 하나에 수백 개 파일의 공개 여부가 동시에 뒤집히는데, 그 순간 파일을 public 버킷으로 옮기거나 버킷 정책을 다시 쓰면 부분 실패 시 공모전이 반쯤 공개된 상태로 멈춘다. 모든 파일은 영구히 private 버킷에만 두고, 앱은 바이트를 거치지 않고 presigned URL만 발급한다. 공개 여부는 발급 시점에 DB 상태를 보고 판정한다.

## Consequences

마감 시각에 파일은 한 바이트도 움직이지 않으므로 "공개 전환 실패"라는 상태가 존재하지 않는다. dev는 MinIO, staging/prod는 S3·OCI로 같은 API를 유지한다. 대가로 공개된 제출물도 매번 URL을 발급받아야 해서 CDN 캐싱 이점을 그대로 누리지 못한다.
