# 파일은 항상 private 버킷에 두고 presigned URL로만 접근한다

Status: Amended by ADR-0030, ADR-0032 (2026-08-28 결정)

제출물에는 수백 MB짜리 앱 빌드와 시연 영상이 들어오는데, 마감 직전 동시 업로드가 앱 워커를 점유하면 마감 자체가 깨진다. 더 큰 문제는 접근 제어다 — 마감 시각 하나에 수백 개 파일의 공개 여부가 동시에 뒤집히는데, 그 순간 파일을 public 버킷으로 옮기거나 버킷 정책을 다시 쓰면 부분 실패 시 공모전이 반쯤 공개된 상태로 멈춘다. 모든 파일은 영구히 private 버킷에만 두고, 앱은 바이트를 거치지 않고 presigned URL만 발급한다. 공개 여부는 발급 시점에 DB 상태를 보고 판정한다.

## Consequences

마감 시각에 파일은 한 바이트도 움직이지 않으므로 "공개 전환 실패"라는 상태가 존재하지 않는다. dev는 MinIO, staging/prod는 S3·OCI로 같은 API를 유지한다. 대가로 공개된 제출물도 매번 URL을 발급받아야 해서 CDN 캐싱 이점을 그대로 누리지 못한다.

**서버가 오브젝트를 쓰는 경로가 하나 있다 — e2e 시드다**(#194). 「앱은 바이트를 거치지 않는다」의 명시적 예외다. `StorageAdapter.write_object` 가 그것이고, 실제 업로드(브라우저의 presigned PUT)를 흉내내 제출물 소스를 미리 채운다 — 그 시드들은 소스를 쓴 뒤 **같은 프로세스에서** 채점 스캔을 돌려 Score 를 만들어야 하기 때문이다.

예외를 계약에 둔 이유는 대칭이다: `read_object` 도 서버 프로세스가 자기 자격증명으로 오브젝트에 직접 붙는 경로이고 채점이 실제로 그것을 쓴다. 쓰기만 fake 어댑터에 두면 그 비대칭이 **「시드는 fake 스토리지에서만 돈다」**는 제약이 되어, e2e 러너에 파이썬 툴체인과 DB 포트 노출을 남긴다(#194 가 그 사슬을 적는다).

**정상 운영에는 이 메서드를 부르는 코드가 없다.** 유일한 호출자인 시드는 `IS_DEPLOYED_ENVIRONMENT` 에서 스스로 거부하고, 그 HTTP 입구(`/api/internal/e2e/seed/{name}`)도 같은 판정을 먼저 한다.
