# 무료 공모전을 MCP 로 만들고 관리하고, 공모전에 보관(소프트 삭제)을 둔다

Status: Accepted (2026-11-05 결정)

## 맥락 (#870)

대표가 무료 공모전을 외부 AI 앱(claude.ai 커넥터·Claude Code)에서 만들고 고치고 관리하게 하기로
했다. 연결된 앱의 OAuth·MCP 몸은 ADR-0069 가 공유층(`core`)으로 올렸고, 허락에 범위(`scope`)를
달았다. 남은 결정은 공모전 쪽의 자원·권한·도구, 그리고 「지우기」를 어떻게 할지였다.

## 결정

1. **새 자원 하나 — 공개 앱의 `/mcp`, 범위 `contests`.** 공개 앱(frontend)이 `/mcp`·
   `/.well-known/oauth-*`·`/oauth/{register,token,revoke}` 를 백엔드 `/api/contests/*` 로 넘긴다.
   강의실 `/mcp` 와 도메인이 달라 겹치지 않는다. 동의 화면은 공개 앱의 `/oauth/authorize`, 연결
   보기·끊기는 「내 정보」에 둔다. 범위가 다른 토큰은 서로의 자원에서 401 이다.
2. **허락은 사용자 본인 계정에 묶는다.** 공용 관리자 키는 없다.
3. **쓸 수 있는 사람 = 개최 권한이 켜진 사용자.** 운영자(`is_staff`)도 같은 검사를 받는다. 동의
   단계(403)와 MCP 호출마다(403) 다시 본다 — 권한을 끄면 그 순간부터 모든 호출이 거절된다.
4. **범위**: 개최자는 자기 sponsor 의 무료 공모전만, 운영자는 모든 무료 공모전. 남의 것·유료·없는
   것은 같은 404 로 거절한다(있는지를 알리지 않는다). 만들기는 늘 부른 사람 명의다. 상금·`is_free`
   인자는 이름만으로 거절한다.
5. **웹과 MCP 는 같은 서비스 함수를 부른다** — 개최·공개·수정·요구사항·수상의 몸을 API 뷰에서
   빼냈다(`contests.api.create_free_contest_draft` 등, `awards.api.award_contest_submission`).
6. **「지금 마감」은 마감 스캔과 같은 간선(`contest-close`)이다.** 마감 시각을 지금으로 당기고
   같은 심사 종료 시각을 넣어 간선을 직접 잡는다. 마감 스캔도 알림을 보내지 않으므로 빠지는
   알림은 없다.
7. **보관 = `Contest.archived_at`(소프트 삭제).** 영구 삭제 도구는 없다. 초안·끝난 공모전·제출
   0건인 공개 공모전만 보관한다. 보관하면 공개 목록·상세(소유자 말고는 404)·검색·홈·강의실
   들여오기에서 빠진다. 상태(`status`)를 바꾸지 않는 표지라 상태 흐름에는 간선이 없다. 「내
   공모전」과 운영자 무료 목록은 그대로 보인다(회귀 없게).
8. **되돌릴 수 없거나 참가자에게 닿는 도구는 두 단계**(지금 마감·수상작 선정·보관·해제) — 강의실과
   같은 확인 표(`core.mcp_confirmation`)다. 쓰기는 `ContestConnectedAppWrite` 에 남는다.
9. **참가자 개인정보는 표시 이름·낸 시각·수상 여부만** 돌려준다. 이메일·실명은 없다.

## 결과

- 공개 앱 백엔드에 `CODEMIT_WEB_ORIGIN` 이 들어간다(메타데이터의 issuer·resource). 비면 공개 앱이
  실어 보낸 오리진을 쓴다.
- 보관이 생겨 공개 질의가 `archived_at IS NULL` 을 하나 더 건다. 새 공개 질의를 더할 때 잊으면
  보관한 공모전이 다시 보인다 — `tests/test_contest_mcp.py` 가 목록·상세·들여오기를 본다.
