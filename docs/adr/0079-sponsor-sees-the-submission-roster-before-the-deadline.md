# 개최자는 마감 전에도 제출 명단(표시 이름·낸 시각)을 본다 (ADR-0036 개정)

Status: Accepted (2026-11-19 결정)

## 맥락 (#956)

대표는 공모전 개최자가 **마감 전에** 자기 공모전에 누가 언제 냈는지를 볼 수 있게 하기로 결정했다.
웹에는 그 자리가 없었다. 마감 전 개최자가 볼 수 있던 것은 다음과 같다(2026-11-19, `22ed7143`).

- 제출 수(`ContestOut.submission_count`, 공개)와 지표(일자별 누적·충족 분포, 이름 없음).
- 단건 조회 `GET /api/submissions/{id}`. id 를 알면 데모·영상·스크린샷·테스트 계정·자가 응답이
  보인다(REQUEST.md 「공개 시점」, ADR-0027 「진행 중엔 본인·Sponsor」).
- 무료 공모전의 MCP `list_submissions`. 표시 이름·낸 시각·수상 여부를 준다(ADR-0070 9번).

ADR-0036 의 「진행 중에는 아무것도 열리지 않는다」는 이 실제 규칙과 어긋났다. 진행 중 비공개는
**Developer 사이의 규율**이고(REQUEST.md, ADR-0027), 개최자에게는 데모·영상·스크린샷이 진행 중에도
열려 있었다.

## 결정

1. **명단 = 표시 이름 + 낸 시각.** `GET /api/contests/{id}/submissions/roster` 가
   `{contest_id, entries: [{display_name, submitted_at}]}` 를 낸 시각 순으로 준다. 마감 전후를
   가리지 않는다.
2. **보는 사람은 그 공모전의 개최자 본인뿐이다.** 남은 403, 없는 공모전은 404, 비로그인은 401.
   다른 참가자와 일반 공개는 바뀌지 않는다.
3. **제출 id·developer id·자료·자가 응답·완성도·점수는 싣지 않는다.** 명단이 단건 조회로 가는
   길잡이가 되지 않게 한다. 수상 여부도 싣지 않는다 — 마감 전에는 늘 거짓이고, 마감 뒤에는 비교
   화면이 이미 보여 준다. ADR-0070 9번의 MCP 칸(표시 이름·낸 시각·수상 여부)보다 하나 좁다.
4. **탈퇴자는 이름 없이 한 줄로 선다**(ADR-0025). `display_name` 이 null 이다.
5. **유료·무료·강의실 경유(「공모전에도 내기」) 제출이 같은 규칙이다.** 강의실 들여오기도 같은
   `ContestSubmission` 행이고 경유를 가리키는 칸이 없다(ADR-0054).
6. **바꾸지 않는 것.** 단건 조회의 마감 전 개최자 열람, 비교 화면의 마감 전 403, 소스·저장소의
   Award 전 비공개(ADR-0014·0027), 가산의 마감 뒤 규칙(ADR-0073).

## ADR-0036 바로잡기

ADR-0036 의 「진행 중에는 아무것도 열리지 않는다」는 **Developer 와 일반 공개에 대한 말**로 읽는다.
진행 중 개최자는 데모·영상·스크린샷(단건 조회)과 이 명단을 본다.

## 결과

- 공개 앱 콘솔 「내 공모전」 줄에 「제출 명단」 링크가 늘 서고, `/console/contests/{id}/roster` 가
  표시 이름·제출 시각 표를 그린다.
- 대표가 「명단만 더하고 상세는 그대로」로 정했다(2026-11-19). 명단 화면은 상세로 가는 링크를 달지
  않고 제출 id 를 쓰지 않는다. 마감 전 개최자의 단건 열람을 나중에 닫으면 이 ADR 의 6번과
  REQUEST.md 「공개 시점」 표를 같이 고친다.
- 되돌리려면 라우트와 화면을 지운다. 저장하는 데이터가 없어 마이그레이션은 없다.
