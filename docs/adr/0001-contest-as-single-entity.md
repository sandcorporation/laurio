# Contest를 단일 엔티티로 둔다

요구사항 명세(Brief)와 경쟁 회차(Round)를 분리하면 유찰 후 같은 명세로 재개최하기가 쉬워지지만, 모든 조회·권한·URL에 회차가 따라붙어 복잡도가 상시로 오른다. 유찰 재개최는 드문 경로라고 판단해 `Contest` 하나에 요구사항·체크리스트·상금·기한을 모두 담고, 재개최는 복제 후 새 Contest가 `source_contest_id`로 원본을 가리키는 방식으로 처리한다.

## Consequences

재개최된 Contest는 원본과 별개의 레코드이므로 결제·제출·정산 이력이 섞이지 않는다. 대신 "이 요구사항은 몇 번째 시도인가"를 보려면 `source_contest_id` 체인을 따라가야 한다.
