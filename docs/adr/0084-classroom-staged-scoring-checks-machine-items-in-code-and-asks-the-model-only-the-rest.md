# 강의실 staged 채점 — 기계로 되는 항목은 코드가, 남은 판단만 모델이

Status: Accepted (2026-11-22 결정)

강의실 채점(클래스 키, 한 번 호출) 옆에 **staged 갈래**를 붙인다. 운영 설정 `CLASSROOM_SCORING_PIPELINE` 이 `staged` 일 때만
타고, 기본값 `single_call` 은 지금 그대로다(프롬프트·저장 기록·응답이 한 바이트도 바뀌지 않는다). 이 ADR 은 갈래의 뼈대와
첫 걸음(기계 판정)을 정한다 — 뒤 걸음(근거 대조·의심 올림·큰 제출 두 걸음)은 같은 스펙(#1282)의 다음 티켓이 이 갈래에 더한다.

## 맥락 (스펙 #1282, 티켓 #1283, 대장 #5329, 조율자 #5332)

강의실 채점은 체크리스트 항목 모두를 한 번 호출 하나에 맡기고 소스를 통째로 싣는다. 운영 읽기 전용 조사에서 체크리스트
판정의 26% 가 기계로 확인되는 꼴이었다(정적 19%·실행 7%). 「`src/app.py` 가 있다」 같은 항목도 모델이 판정하니 흔들리고
토큰을 쓴다. 대표 결정은 에이전트니 한 번 호출이니를 고르는 대신 **모델에게 맡기는 양을 줄이는** 꼴이다 — 기계로 되는 것은
기계로, 판단만 싼 모델로, 의심만 위로. 비싼 방식(에이전트)은 공모전과 에이전트로 정한 클래스에 남는다.

## 결정

1. **켜고 끄는 운영 설정 하나.** `CLASSROOM_SCORING_PIPELINE` = `single_call`(기본) | `staged`(운영 설정 화면, ADR-0075 의
   choice). 값이 없거나 모르면 `single_call`. 에이전트 방식 클래스(`Class.scoring_method=agent`)는 이 값을 보지 않는다.
   설정은 준비의 앞 절반(DB 를 쓰는 쪽)에서 읽는다 — 뒤 절반(소스 읽기)은 DB 를 쥐지 않는다(#584).
2. **기계 확인 규칙은 체크리스트 항목의 칸이다.** `ChecklistItem.machine_rule`(JSON, 비면 「판단」 항목). 꼴은 정적인 셋만 —
   `path_exists`(경로·glob), `file_contains`(경로 glob + 고정 문자열 또는 정규식), `config_value`(JSON·YAML·TOML·.env 의 키 =
   값). 강사 API·MCP 가 검증된 스키마(`classroom.schemas.MachineRuleIn`)로만 받는다. 참여자 응답에는 싣지 않는다. 같은 클래스
   안 문제 복사는 규칙을 옮기고, 템플릿·공모전 문제는 아직 옮기지 않는다(템플릿 사본 모델에 칸이 없다). 화면은 대표 결정을
   기다린다 — 이 결정에서는 API·MCP 까지만.
3. **판정기는 순수 함수, 트리는 채점이 읽은 원본 그대로.** `classroom.machine_check.judge(rule, tree)`. 트리는 프롬프트 선별
   (`core.source_selection`)의 예산·「코드 아님」 제외를 따르지 않는다 — 규칙은 강사가 경로를 콕 집어 쓰므로 `tests/`·`docs/`
   를 빼면 「시험 폴더가 있다」가 늘 미충족이 된다. 벤더·빌드 폴더만 뺀다. zip 목록은 풀지 않고 읽고, 내용은 파일 하나 1MB
   까지만 읽는다. glob 은 앞 폴더를 건너뛰어도 맞는다(GitHub zip 의 `<저장소>-<sha>/`).
4. **판정은 셋, 「판정 불가」는 모델에게 넘긴다.** 충족·미충족·판정 불가. 미충족은 확인할 것을 모두 읽었는데 없을 때만이다.
   파일을 못 읽음(너무 큼·바이너리·파싱 실패)·정규식 시간 초과는 판정 불가이고, 그 항목은 판단 항목처럼 모델에게 간다 —
   기계가 모르는 것을 미충족으로 굳히지 않는다.
5. **정규식은 자식 프로세스에서 시간 한도(2초) 안에.** 파이썬 `re` 에는 시간 한도가 없고 스레드는 죽일 수 없다. 강사의
   규칙이라도 파국적 되추적 하나가 grader 를 붙잡지 않게 한다. 길이(200자)·문법은 저장할 때 막는다.
6. **모델에게는 남은 항목만, 결과는 지금과 같은 `ClassroomScore`.** 프롬프트는 지금 함수(`_build_prompt`)에 남은 항목만
   넘겨 짓는다 — 크기 초과 보류(#989)도 그 프롬프트로 잰다. 두 결과를 체크리스트 순서로 합쳐 점수 하나를 만들고, 점수 셈은
   지금 함수 그대로다. 판단 항목이 없으면(문법 검사의 AI 몫도 없으면) **벤더를 부르지 않는다** — 토큰 0, 키 확인 기록 없음,
   `model_version` 은 `machine-check-v1`. 결과 쓰기·알림은 벤더를 부른 채점과 같은 길이다.
7. **출처는 기록에 남긴다.** staged 의 판정 항목마다 `source`(`machine`|`model`)를, 기계 판정에는 `evidence`(경로[:줄])를 함께
   저장한다. 기계 판정의 근거 문장은 「기계 판정 — 」으로 시작해 화면에 그대로 보인다. single_call 의 기록에는 이 칸이 없다.

## 바꾸지 않는 것

시도당 Score 하나·다시 채점하지 않음(ADR-0006), 임대 세 걸음(`classroom/scoring.py` 머리말), 강사 키로 돎, 크기 초과 보류
(#989), 공모전 채점(에이전트·한 번 호출). 운영 점수를 다시 매기지 않는다.

## 대가

- 기계 판정이 한 번 더 zip 을 연다(목록 + 규칙이 가리키는 파일만). 규칙이 없는 문제는 열지 않는다.
- 정규식 규칙마다 파이썬 자식 프로세스 하나(수십 ms)가 뜬다.
- 템플릿으로 옮긴 문제는 규칙을 잃는다 — 템플릿 칸은 화면 결정과 함께 더한다.
