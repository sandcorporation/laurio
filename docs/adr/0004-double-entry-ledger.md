# 정산은 복식부기 원장으로 기록한다

Status: Accepted (2026-08-28 결정)

하나의 입금(상금 + 개최 등록비)이 여러 출금으로 쪼개진다 — 1/N 배분 대상 N명, 플랫폼 수수료, 원천징수, PG 수수료. 여기에 1/N 나머지(500만원 ÷ 3 = 나머지 2원)까지 얹힌다. `Contest`에 금액 컬럼을 두거나 Payout 테이블만 두는 방식으로는 "이번 달 에스크로에 들어온 돈과 나간 돈이 1원 단위로 맞는가"에 답할 수 없다. 계정과목을 두고 차변 합 = 대변 합을 강제하는 복식부기 원장을 쓴다.

## Consequences

계정과목: 발주자 예치금 / 개발자 미지급금 / 플랫폼 수수료 수익 / 원천징수 예수금 / PG 수수료 비용. 원천징수액은 국세청에 낼 남의 돈이므로 반드시 별도 계정으로 분리한다. 금액은 원 단위 정수로 다루고, 1/N 나머지도 단수처리 분개로 명시되어 사라지지 않는다. 정정은 행 수정이 아니라 반대 분개 추가로만 하므로 원장은 append-only이고 감사 흔적이 그대로 남는다. 회계 지식이 필요한 만큼 초기 개발 속도는 느려진다.
