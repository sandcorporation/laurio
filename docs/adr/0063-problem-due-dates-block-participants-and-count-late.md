# 문제마다 권장 기한과 마감을 둔다 — 마감은 참여자의 새 시도를 막고, 늦음은 시도에 박지 않고 볼 때마다 다시 셈한다

Status: Amended by ADR-0078 (2026-10-21 결정)

> 마감으로 새 시도를 막는 규칙과 boolean 늦음은 ADR-0078에서 바뀌었다. 아래는 2026-10-21의 결정이다.

## 맥락 (#769)

강의실 Problem 은 「마감이 없다」가 정의의 일부였다 — `CONTEXT.md` Problem 항목, `Problem` 모델
docstring, 그리고 제출 모델을 부모·자식으로 가른 ADR-0039 의 전제(강의실 제출은 마감도 재도전
제한도 없어 공모전의 유니크 제약을 지지 않는다)가 그렇게 말했다. 강사들이 문제마다 「이때까지
내라」와 「이 뒤로는 안 받는다」를 따로 두고 싶어 했다(2026-10-21). 시안은
`docs/design/classroom-deadline/`.

## 결정

- 대상은 **Problem 하나하나**다. 클래스 전체의 기한은 없다.
- 두 날짜 — **권장 기한**(`recommended_due_at`)과 **마감**(`due_at`). 둘 다 nullable 이고, 둘 다
  있으면 권장 ≤ 마감(같은 시각 허용), 어기면 422.
- **마감이 지나면 참여자는 새 시도를 내지 못한다**(403, `submit_blocked_reason` = `deadline_passed`,
  보관 → 내보냄 → 숨김 → 마감 순). 문제는 목록에 그대로 보이고 지난 시도·판정도 그대로 본다.
  **강사·공동 강사는 언제나 낸다**(문제를 점검하는 것이 정상 절차다, 2026-09-17 의 결정 그대로).
- **권장 기한이 지나도 낼 수 있다.** 그 뒤의 시도는 「늦음」(`late` = 제출 시각 > 권장 기한)이고,
  **저장하지 않고 응답마다 계산한다.** 참여자 목록 줄·강사 격자 칸은 마지막 시도 기준이다.
- 날짜는 언제든 앞뒤로 옮긴다(돈이 걸려 있지 않다). 템플릿 공개·클래스 복사·문제 복사·템플릿
  가져오기는 두 날짜를 비운다. 채점 중에 마감이 지나도 그 시도는 끝까지 채점된다. 보관된
  클래스에서는 날짜도 못 고친다. 마감이 지난 초안을 여는 것은 막지 않는다.
- 공모전 문제에도 강사가 둔다 — 공모전 자체의 마감과 별개. 마감이 지나면 시도 자체가 안 만들어지므로
  「공모전에도 내기」도 함께 막힌다.
- 알림(마감 임박·지남)은 범위 밖.

## 고려한 대안

- **표시만 하고 막지 않는다** — 「마감」이 강사에게 뜻하는 것이 「그 뒤로는 안 받는다」라서, 받으면서
  표시만 하면 강사가 손으로 걸러야 한다. 그 자리는 권장 기한이 맡는다: 막지 않고 늦음만 표시한다.
  둘을 나눠 두면 강사가 「받되 늦었다고 보인다」와 「안 받는다」를 고른다.
- **늦음을 시도에 박는다**(제출 시각에 판정해 저장) — 날짜를 옮기면 지난 판정이 그대로 남아 화면이
  지금 날짜와 어긋난다. Problem 의 원칙은 「고치면 지난 점수는 남고 달성률만 다시 셈한다」이고 늦음도
  같은 결이다 — 점수가 아니라 셈이다. 그래서 `created_at` 과 지금 값을 견줘 응답마다 센다.

## 결과

- `Problem.recommended_due_at`·`Problem.due_at`(마이그레이션 0033, 둘 다 NULL 기본 — ADR-0053 대로
  먼저 돌아도 옛 코드가 견딘다). 모델 docstring 과 `CONTEXT.md` 의 「마감이 없다」는 지금 사실로 고쳤고,
  ADR-0039 는 그때의 판단으로 남는다 — 제출을 부모·자식으로 가른 결정 자체는 그대로다(마감이 있어도
  한 사람 한 제출로 묶지 않는다).
- `classroom.participation.SUBMIT_BLOCKED_DEADLINE_PASSED` 가 제출 POST 와 `submit_blocked_reason`
  둘 다를 같은 기준으로 막는다. 채점은 이 함수를 부르지 않아 마감이 채점을 건드리지 않는다.
- `late` 는 시도 응답(참여자용·강사용·최근 시도)과 참여자 목록 줄·격자 칸에 실린다.
- MCP `create_problem`·`update_problem` 이 같은 칸을 받는다(ISO 8601, 고치기는 생략하면 그대로·null
  이면 비운다).
- 화면은 #770 이, 알림은 다음 티켓이 맡는다.
