# 강의실 채점 판정에 「확인 불가」를 더한다 — 강의실만, `is_met` 은 그대로, 확인 불가는 충족이 아니다

Status: Accepted (2026-10-28 결정)

## 맥락 (#811)

강의실 채점은 제출한 소스 텍스트를 모델에 한 번 보낼 뿐이다(도구·접속·실행 없음). 판정이 `is_met: bool`
하나라 「공개 주소가 실제로 리디렉션된다」 같은 실행·접속형 항목도 충족·미충족 중 하나로 갈렸고, README 의
주장을 믿느냐에 따라 시도마다 흔들렸다(클래스 6 문제 59, #805). #805·#810 은 만들 때 알리는 안내를 더했지만,
이미 그런 항목이 있는 문제의 판정은 여전히 흔들린다.

## 결정 (사용자 선택 A1·B1·C1·D0)

- **강의실만, `is_met` 유지 + `verdict`.** 판정은 `met`·`unmet`·`unverifiable` 이다. 강의실 어댑터만
  `allow_unverifiable=True` 로 만들어 스키마가 `is_met` 대신 `verdict` 를 받는다(둘을 함께 받으면 어긋난 응답을
  어느 쪽으로 읽을지 정해야 해 하나만 받고, `is_met` 은 파서가 `verdict == "met"` 으로 만든다). 저장
  (`ClassroomScore.reasoning`, JSON 이라 마이그레이션 없음)은 둘 다 들고, 옛 기록은 `is_met` 에서 유도한다 —
  유도 규칙은 `classroom.verdicts` 한 자리. REST·MCP 는 `is_met` 을 그대로 두고 `verdict` 를 더한다(MCP 출력
  스키마에서는 선택 필드 — 외부 클라이언트 호환).
- **확인 불가 = 충족 아님.** 통과·달성률·명단 격자·`met_count` 는 `is_met` 만 본다. 필수 항목이 확인 불가면
  통과하지 못한다 — 그 길은 항목을 「…하는 코드가 있다」로 고치거나 필수에서 빼는 것이다(#805·#810 의 안내).
- **학생 화면에 세 번째 표시.** 점선 테두리 표식과 「확인 불가」 배지·sr-only 문구. 새 색을 만들지 않는다.
- **강사 수동 판정은 만들지 않는다.**
- **프롬프트**: 「확인할 수 없는 것」 목록을 MCP·화면 안내(`classroom.gradability_hint`)와 같은 말로 쓰고, 정적으로
  판정할 수 있으면 미루지 말라는 문장을 짝으로 둔다. 문장은 강의실 프롬프트(`_build_prompt`)에만 있다 — core 의
  시스템 프롬프트는 공모전과 함께 쓴다.

## 공모전을 바꾸지 않은 이유

공모전 채점(`scoring.services` → `core.llm_scoring.get_adapter()`)은 같은 `RequirementVerdict`·스키마·파서를 쓰지만,
공모전 점수는 상금·심사·이의 제기에 걸려 있어 판정 모양을 바꾸면 백분율·이의 흐름·심사 화면이 함께 흔들린다.
강의실은 돈이 걸려 있지 않고 판정이 학습 안내라 먼저 바꿀 수 있다. 그래서 스위치는 어댑터 생성 인자
(`allow_unverifiable`, 기본 `False`)이고 공모전 경로는 그 인자를 주지 않는다 — 시험이 공모전 스키마·파서가
`verdict` 를 요구하지 않음을 지킨다.

## 결과

- 모델이 어려운 항목을 확인 불가로 **미루는 쏠림**은 녹화 응답 시험이 못 잡는다 — `manage.py
  measure_unverifiable_verdicts` 가 실행·접속형 4·정적 4 항목으로 실제 모델의 비율을 잰다(키는 환경변수에서만,
  어림 500원 상한).
- 확인 불가가 필수 항목에 남은 문제는 아무도 통과하지 못한다. 그 문제를 고치는 것은 강사의 몫이다.
