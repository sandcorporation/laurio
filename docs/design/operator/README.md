# 운영자 앱 디자인 시안 (2026-09-16)

`python3 gen.py` 로 다시 만든다. 브라우저로 `*.dc.html` 을 열면 그대로 보인다 —
1440×1020 캔버스에 인라인 스타일뿐이고, 강의실 시안(`../classroom/`)과 같은 방식이다.

**이 시안이 답하려는 것**: 운영자 앱은 화면이 열둘인데 지금은 640px 한 칸에 카드만
쌓여 있고, 공개 앱·강의실과 생김이 다르다(Tailwind·토큰 없이 요소 스킨 CSS 뿐이다).
한 사람이 세 앱을 오가는데 생김이 갈리지 않아야 하고, 운영은 표를 읽는 일이다.

## 정한 것

- **색은 같은 토큰이다** — 먹·종이·뜬 면·괘선·통과 초록·주의 빨강 여섯. 운영자만 다른
  정체성을 주지 않는다(`_lib.py` 의 `LIGHT`/`DARK` 가 `tokens.css` 의 `light-dark()`
  두 값 그대로다).
- **왼쪽에 좁은 내비, 본문은 넓은 표.** 항목을 「할 일 · 기준 · 운영」 셋으로 묶는다 —
  지금 내가 처리할 일(이의·지급·신고)과, 바꾸면 서비스가 흔들리는 것(정책·카테고리·
  산출물 종류)과, 계정·권한·알림을 한 바구니에 담지 않는다.
- **행은 촘촘하다.** 카드보다 표다. 숫자는 고정폭으로 세로줄이 맞는다.
- **대기는 중립 배지 + 글자로 가른다.** 지금 CSS 는 지급 대기 셋을 파랑·노랑·초록
  배경으로 갈랐는데, 이 브랜드의 상태색은 둘(통과·주의)뿐이고 **대기는 실패가
  아니다** — 그래서 색으로 겁주지 않고 「무엇을 기다리나」와 「누구 차례」 두 칸으로
  가른다(ADR-0020 의 「돈은 움직이지 않고 사람이 본다」와 같은 생각).
- **다크는 토큰만 갈아 끼운다** — `Payouts.dark.dc.html` 이 그 증명이다. 운영자 앱에는
  아직 토큰 파일도 테마 토글도 없으니, 구현할 때 그 둘이 함께 온다.

## 화면 넷

| 파일 | 무엇을 보여주나 |
| --- | --- |
| `Home.dc.html` | 「할 일」 — 큐 셋의 건수와 가장 오래 밀린 것, 그 아래 최근 변경 이력(누가·언제, ADR-0023) |
| `Appeal.dc.html` | 이의 심판 상세 — 왼쪽에 판단 근거(이의 사유·채점 결과·열람 수단), 오른쪽에 심판 패널과 감사 추적. 확정이 되돌릴 수 없다는 것을 그 자리에서 말한다 |
| `Payouts.dc.html` | 지급 큐 — 필터 탭과 넓은 표. 대기 셋을 중립 배지로 가르고 「누구 차례」를 한 칸으로 세운다 |
| `OperatorNotice.dc.html` | 운영팀 알림 보내기 — 받는 사람 → 작성(이미지) → 확인 세 단계와 발송 이력. 비공개 저장소·append-only 라는 약속을 화면이 말한다 |
| `Payouts.dark.dc.html` | 같은 지급 큐의 다크 |

## 시안이 정하지 않은 것

- **구현 범위와 순서.** 공통 골간(내비·표·토큰)을 먼저 세우고 화면을 옮기는 편이
  자연스럽지만, 그 쪼개기는 스펙·티켓의 몫이다.
- 남은 화면 여덟(정책·카테고리·산출물 종류·운영자 계정·개최 권한·무료 공모전·
  템플릿 신고·로그인)의 세부. 넷이 홈·상세·표·폼 네 꼴을 덮으므로 나머지는 그 꼴을
  따른다.
- 좁은 화면(태블릿·휴대폰)에서 내비가 어떻게 접히는가. 운영자 앱은 책상에서 쓰는
  화면이라 이 시안은 1440 하나만 그렸다.
