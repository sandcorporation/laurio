강의실 기한 시안

문제마다 권장 기한과 마감을 둔다. v2 시안(2026-10-14)의 화면에서 기한이 닿는 일곱 장만 다시 그렸다 — 색·서체·괘선·조각은 v2 와 같고, 달라진 자리는 장마다 아래에 적었다.

합의한 규칙

  • 대상. Class 안의 Problem(문제) 하나하나. 클래스 전체의 기한은 없다.
  • 두 날짜. 권장 기한과 마감. 각각 선택이고, 둘 다 있으면 권장 ≤ 마감. 시각까지 저장하고 화면은 날짜·시각을 고르되 시각 기본값은 23:59(브라우저 로컬).
  • 마감이 지나면. 참여자는 새 시도를 낼 수 없다. 문제는 목록의 같은 자리에 「마감 지남」으로 남고, 지난 시도·판정은 그대로 본다. 강사·공동 강사는 언제나 낸다.
  • 권장 기한이 지나면. 낼 수 있다. 그 뒤에 낸 시도는 「늦음」 — 참여자 본인 화면과 강사 격자 둘 다에 보인다.
  • 붉은 글자. 참여자가 아직 통과하지 못한 문제의 지난 마감에만. 이미 통과한 문제와 강사 화면의 지난 마감은 흐린 글자다 — 붉음은 「네가 할 일이 막혔다」는 뜻 하나로 둔다.
  • 다시 셈한다. 「늦음」·「마감 지남」은 시도에 박지 않고 지금 날짜 기준으로 셈한다. 날짜는 언제든 앞뒤로 옮길 수 있다 — 체크리스트를 고치면 달성률만 다시 셈하는 것과 같은 결.
  • 따라가지 않는다. 템플릿·클래스 복사·다른 클래스의 문제 복사에서 날짜는 비운다. 공모전 문제에도 강사가 둔다(공모전 자체의 마감과 별개).
  • 범위 밖. 알림(마감 임박·마감 지남)은 다음 티켓. 백엔드 회전 유예 같은 다른 일과 섞지 않는다.
  • 용어집. Problem 항목의 「마감이 없고」를 고치고 「권장 기한」·「마감」·「늦음」을 화면 말로 올린다. 피하는 말의 「마감」은 「숨김을 마감이라 부르지 않는다」로 좁힌다. 짧은 ADR 하나.

이 문제의 진행
3/4
  • 「제출」 카드 머리에 「마감 지남」 배지, 그 아래 마감 시각 한 줄. 끌어다 놓기·저장소 칸·「제출하기」는 흐려진 채 남는다 — 무엇이 막혔는지는 보이되 누를 수 없다.
  • 설명·체크리스트·지난 시도와 판정은 전부 그대로 읽는다 — 제출과 판정은 참여자의 기록이다(숨김과 같은 원칙).
  • 강사·공동 강사가 「학생 화면으로」 들어오면 이 카드가 막히지 않는다 — 강사는 언제나 낸다.
  • 백엔드는 제출 POST 에 새 차단 이유 하나(마감 지남)를 더하고, 조회 응답의 submit_blocked_reason 으로 미리 알린다 — 보관·내보냄·숨김과 같은 길이다.

코드가 따라가려면

백엔드

  • Problem 에 nullable 시각 둘(권장 기한·마감). 만들기·고치기 API 와 MCP 의 create_problem·update_problem 이 같은 필드를 받는다. 둘 다 있으면 권장 ≤ 마감을 422 로 지킨다.
  • 제출 POST 의 차단 이유에 「마감 지남」 하나 — 순서는 보관 → 내보냄 → 숨김 → 마감. 강사·공동 강사는 건너뛴다. 조회 응답의 submit_blocked_reason 도 같은 값을 낸다.
  • 시도·격자·문제 목록 응답에 「늦음」을 계산해서 싣는다(제출 시각 > 권장 기한). 저장하지 않는다.
  • 템플릿 공개·클래스 복사·문제 복사가 두 필드를 비운다.

강의실 앱

  • 문제 편집: 「기한」 카드(날짜·시각 입력 둘, 비우기, 순서 검사).
  • 문제 표·격자 머리·참여자 목록·제출 카드: 기한 표기 조각 하나를 나눠 쓴다(권장 흐리게 · 마감 보통 · 지난 마감 붉은 배지).
  • 격자 칸의 늦음 점, 시도 줄과 목록 줄의 「늦음」 배지, 제출 카드의 「마감 지남」 상태.
