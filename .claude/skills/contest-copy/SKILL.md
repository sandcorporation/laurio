# 공모전 문구 쓰기

Codemit 공모전 상세의 「설명」 칸에 들어가는 글이다. 개최 폼에서 그 칸에 붙이면 참가자가
공모전 상세에서 읽는다.

**이 스킬이 있는 이유.** 2026-09-16 에 개최한 첫 무료 공모전의 설명이 「너무 AI 가 쓴 어투」
라는 지적을 받았다. 실제 공모전 공고들을 읽어 무엇이 다른지 재어 보니 세 가지가 갈렸고, 그
셋은 취향이 아니라 **세는 것**이다(아래 「어투」). 그때 고친 글이 지금 prod 1번 공모전이다.

## 먼저 — 무엇이 이 칸에 들어가고 무엇이 안 들어가는가

**요구사항 체크리스트는 이 칸이 아니다.** 초안 편집 화면(`/console/contests/{id}/draft`)의
**별도 칸**이고, 심사·채점이 보는 것은 그쪽이다. 설명에 요건을 적는 것은 읽는 사람을 위한
안내일 뿐 판정 근거가 아니다 — 그래서 둘이 어긋나면 체크리스트가 이긴다. 설명에 요건 표를
둘 때는 체크리스트에 실제로 넣은 항목과 **같은 말**로 쓴다.

**무료 공모전에는 화면이 이미 고정 문구를 띄운다.** 상세 맨 위에 「무료 공모전입니다 — 상금
없이 열리며, 개최자가 설명에 적은 보상은 플랫폼이 보증하지 않습니다. 수상작의 소스는
개최자가 볼 수 있습니다.」가 항상 붙는다. 그래도 「시상」 항목에 **같은 사실을 한 번 더**
적는다 — 보상을 읽는 자리에서 그 단서를 함께 읽어야 한다.

## 이 서비스의 렌더러가 그리는 것 (ADR-0047)

설명은 **마크다운**으로 그려진다. 허용 목록 방식이라 목록에 없는 것은 조용히 사라진다.

- **되는 것**: 제목(`##`~`######`), 문단, 굵게·기울임·취소선, 목록(번호·글머리·체크박스),
  **표**(열 정렬 포함), 인용, 수평선, 인라인 코드, 코드블록, 링크, 이미지.
- **안 되는 것**: 원문에 섞은 HTML(통째로 사라진다), `http`/`https` 가 아닌 주소(링크가 아니라
  글자로 남는다).
- **제목 단계가 한 칸 내려간다.** `##` 로 쓴 것이 화면에서 h3 로 그려진다 — 설명의 제목이
  페이지의 h1(공모전 제목)을 넘지 않게 하는 규칙이다. **최상위 항목은 `##` 로 쓴다.**
- **코드블록에는 복사·파일로 저장 버튼이 붙는다.** 언어를 적으면 색이 입혀지고, 정보 줄에
  파일 이름을 적으면(```` ```text map.txt ````) 그 이름으로 저장된다.
- **첫 문단이 검색 결과에 나간다.** 메타 설명은 설명에서 글자만 뽑아 160자에서 자른다 —
  그래서 첫 문단은 「이 공모전이 무엇인가」를 그 안에 담아야 한다.

## 항목 구성 — 실제 공고의 순서

읽어 본 공고들(contestkorea·wevity의 SW 개발 공모전들)은 항목 이름이 정형화돼 있다. 그 순서를
따른다.

| 항목 | 담는 것 |
| --- | --- |
| 공모 주제 | 한 줄 주제 + 무엇을 만드는가 2~3문장. 검색 결과에 나가는 자리다 |
| 대상 | 누구를 상대로 여는가. 제출 단위(개인/팀) |
| 개발 요건 | 필수·선택을 **표**로. 체크리스트와 같은 말로 |
| 개발 범위 | 어디까지 하면 되는지. 항목별로 `**이름** : 내용` |
| 평가 기준 | 무엇을 보는가. 표로 |
| 시상 | `1등 1명 : 상품`. 플랫폼이 보증하지 않는다는 단서 |
| 제출 방법 | `제출물 : …` + 조건 목록 |
| 일정 | 표로 (접수 마감·심사·결과 발표) |
| 유의 사항 | 금지·허용·권고 |

「대상」이라고 쓰고 **「참가 자격」이라고 쓰지 않는다** — 이 플랫폼에는 특정 사람만 받는 문이
없다. 자격이라고 쓰면 지킬 수 없는 규칙을 적는 셈이다.

## 어투 — 세어서 거른다

AI 가 쓴 티는 문장력이 아니라 **분포**로 드러난다. 고친 글의 전후가 그 증거다.

| | 전 | 후 |
| --- | :---: | :---: |
| `—` 로 붙이는 부연 | 14곳 | **0곳** |
| 굵게(`**`) | 26곳 | 7곳 |
| `※` 로 분리한 단서 | 0곳 | 6곳 |
| 표 | 0개 | 4개 |

지킬 것:

- **`—` 부연을 쓰지 않는다.** 「A 를 봅니다 — 그것이 B 이기 때문입니다」 꼴이 AI 티의 1번이다.
  두 문장으로 끊거나, 단서면 `※` 로 내린다.
- **굵게는 항목 이름에만.** 문장 속 강조를 흩지 않는다.
- **단서는 `※` 로 분리한다.** 실제 공고의 관례이고, 본문과 예외가 눈으로 갈린다.
- **값은 콜론으로 붙인다.** 「1등 한 분께 치킨 기프티콘을 드립니다」가 아니라
  `1등 1명 : 치킨 기프티콘`.
- **말 걸기 소제목을 쓰지 않는다.** 「무엇을 만드나」·「하면 더 좋은 것」·「미리 말해 두는
  것」이 아니라 「공모 주제」·「개발 요건」·「유의 사항」.
- **수사적 반전을 쓰지 않는다.** 「못 한 것을 적는 것이 감점이 아닙니다 — 적지 않는 것이
  감점입니다」 → `※ 구현하지 못한 항목을 적는 것은 감점 사유가 아닙니다. 적지 않으면 문서화
  항목에서 감점합니다.`
- **나열은 표로.** 요건·평가·일정은 산문보다 표가 짧고, 공고처럼 읽힌다.

## 지어내지 않는다

- **배점을 지어내지 마라.** 실제 공고는 대개 「적합성 10점·독창성 10점…」을 싣고 그것이
  진짜처럼 읽히는 큰 요인이다. 그래서 넣고 싶어지지만, 그 가중치는 **개최자가 정하는
  값**이다. 정해진 값이 없으면 「순위」 열로 우선순위만 밝히고, 배점을 원하면 개최자에게
  물어라.
- **일정을 늘리지 마라.** 이 플랫폼의 공모전에는 서면심사·멘토링·발표심사 같은 단계가
  없다. 있는 것은 마감·심사·결과 발표뿐이다.
- **없는 절차를 쓰지 마라.** 참가신청서·서약서·개인정보 동의서는 이 서비스에 없다. 제출은
  저장소 주소 하나다.

## 보상·제출의 사실 (틀리면 약속이 거짓이 된다)

- **보상 전달은 서비스 안 알림이다.** 문자·이메일로 보내지 않는다. 그 사실을 적어야 수상자가
  알림을 확인한다.
- **수상작의 소스는 개최자가 열람한다.** 제출이 그 동의다. 수상하지 않은 제출물의 소스는
  열리지 않는다.
- **저장소는 마감까지 공개 상태여야 한다.** 비공개면 열람할 수 없어 심사 대상이 아니다.
- **마감 뒤에는 제출도 수정도 되지 않는다.** 마감 전에는 여러 번 다시 낼 수 있고 마지막
  제출본을 심사한다.

## 쓴 뒤에

1. **개최 폼의 「미리보기」 탭에서 확인한다.** 설명 칸에 「쓰기」·「미리보기」 탭이 있고,
   미리보기는 참가자가 볼 그 렌더러로 그린다. 표와 제목 단계를 여기서 본다.
2. **화면 문자열 규칙을 지킨다.** 한국어로 쓰고, 영어 도메인 용어(`Sponsor`·`Contest`
   등)와 `ADR-숫자`·`#숫자` 참조를 넣지 않는다(`CONTEXT.md` 의 「화면에서」 줄).

## 공개한 뒤에도 제출 기간 중에는 고칠 수 있다 (#473, ADR-0051)

**공개된(published) 공모전의 설명도 `PATCH /api/contests/{id}`로 고친다** —
`update_contest`가 마감 전까지(CLOSED 이전) 통과시킨다. `/console/contests/{id}/draft`
화면이 draft와 같은 편집 자리를 그대로 연다. **마감된 뒤에는 다시 막힌다** — Score가
이미 그 시점의 요구사항을 근거로 만들어졌거나 만들어질 참이라서다(ADR-0006).

**공개 상태에서 실제로 문구를 고치면 이력이 남고 참가자에게 알림이 간다.** `ContestChange`
행이 무엇이 바뀌었는지 남기고, 이미 제출한 참가자 전원에게 「공모전 내용이 바뀌었다」는
알림(`NotificationType.CONTEST_UPDATED`)이 간다 — 조용히 슬쩍 고치는 경로가 아니다. 그래도
공개 전에 미리보기로 문구를 끝내는 것이 여전히 맞다 — 참가자가 이미 그 조건으로 작업 중일
때 고치면 그 사실이 이력·알림으로 드러날 뿐 손해 자체가 없어지지는 않는다.

**마감된 공모전의 설명을 고치는 API 는 여전히 없다.** 그 경우에만 이전처럼 prod DB 를
직접 손대야 한다 — **되돌릴 수 없으므로 원문을 먼저 백업하고, 사람의 확인을 받은 뒤에
한다.** 경로는 `sub` 를 거친다(이 머신에서 prod 로 가는 직접 ssh 는 없다):

```bash
ssh sub "ssh oracle 'docker exec codemit-prod-backend-1 python manage.py shell -c \"...\"'"
```

prod 1번 공모전의 설명을 그렇게 한 번 바꿨다(2026-09-17, #473 이전이라 API 가 아예 없었다).
그때 원문 백업 → 새 글 주입 → `https://codemit.kr/api/backend/contests/1` 로 응답 확인 →
브라우저로 렌더 확인 순서로 했다. 마감된 공모전을 손대야 한다면 같은 순서를 따른다.
